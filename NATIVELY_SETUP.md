# Kinsroot — Natively release setup

Use https://kinsroot.softserge.com as the production website in Natively. The application uses the official `natively` SDK through `src/lib/natively.ts` and `NativelyContext`; do not also inject a second SDK script. Median is retired. Existing Capacitor files and the separate Expo prototype are not the Natively release source.

## Required native configuration
- Use Kinsroot as the app name and `com.softserge.kinsroot` as the Android package identifier. Confirm the intended iOS bundle identifier before creating signing credentials.
- Enable Firebase push in Natively, not OneSignal. Upload the matching Android Firebase configuration and an iOS GoogleService-Info.plist for the actual bundle identifier. Configure APNs credentials in Firebase. Rebuild after enabling these features.
- Use the supplied opaque 1024px icon and 512px Play icon. Store graphics are delivered separately, not served by the website.
- Configure camera/photo permissions for receipt upload and QR scanning. Request notification permission only when the member enables notifications.
- Confirm Google/Apple authentication works in the actual wrapper with external browser handling and a return-to-app link. Browser success is not native OAuth verification.
- Configure badges, sounds and notification deep links in Natively/Firebase. Test on physical iPhone and Android devices, including background and terminated states. The web adapter only obtains the native FCM token; it does not manufacture OS notification behavior.

## Account deletion
Profile includes an English/French deletion confirmation. The endpoint validates the current user, explicit confirmation and a sign-in within 15 minutes. It removes sign-in identities and refresh sessions; a database lifecycle trigger anonymizes the profile, clears direct roles/messages/notification records, and keeps anonymous family financial records. Owned files are removed through the Storage API before auth deletion. No debt is forgiven by deletion. Test using a disposable member before release; never delete a production administrator for QA.

## Remaining store submission checks
- Publish the updated website only after approval; no store binary is generated by this code change.
- App Store Connect/Google Play developer accounts, signing credentials, app ownership and Natively subscription/build settings remain the owner's responsibility.
- Test account deletion with a disposable member, native push delivery, OAuth return links, offline receipts and two-reviewer approvals before submission.
- Provide a public account-deletion request URL for Google Play and a support/privacy URL. The signed-in Profile action alone is not Google's external deletion request resource.
- Complete Apple's privacy labels and Google's Data safety declaration from actual data handling. Include receipt photos, financial data, contact details, identifiers, analytics, and AI processing; do not declare no data collection.
- Store screenshots must show the actual native app, using a consented demo family with no personal data. Do not present a fabricated dashboard as a screenshot.
- Confirm production email sender, reminder delivery, family payment receiving numbers and legal retention policy. Account deletion does not by itself certify legal or store compliance.
